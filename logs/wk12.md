# Week 12 (April 16, 2026) - API Security, Flask Deployment, and How the Web Works

## What I learned this week
- Difference between running a Flask app locally vs. deploying it publicly
- Local app = only runs on `127.0.0.1:5000`
- Deployment = putting the app on a server so other people can access it through a URL
- API keys should not be hardcoded or pushed to GitHub
- `.env` files store secrets locally
- `.env` should be added to `.gitignore`
- Render uses environment variables in the dashboard instead of a local `.env` file
- `requirements.txt` lists the packages needed to run the app
- Flask’s built-in server is for development, not production
- `gunicorn` is used as a production server for deployment
- Frontend = what the user sees, such as HTML, CSS, forms
- Backend = server logic, Flask, Python, APIs
- Full stack = frontend + backend working together
- MP3 counts as a full-stack web app because it has both user-facing pages and backend logic
